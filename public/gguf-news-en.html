Latest GGUF Model News

A daily digest of new and updated models available as GGUF, plus related updates to llama.cpp, Ollama, LM Studio and more. Follow the source links for the primary information. Dates are in JST.

    2026-11-26

    3 items
    llama.cpp Inkling 2 speculative decoding

    llama.cpp adds Inkling 2 DSpark speculative decoding support (#32218)

    The official repo merged DSpark (draft-based speculative decoding) support for Inkling 2, adding conversion and C++ implementation, handling for temperature > 0, fixes to draft state width and reseeding order, and aligning draft token limits with the other DSpark implementations.

    Source: https://github.com/ggml-org/llama.cpp/commit/33aeb17f85869279e3821f746bc645357139bc2c

    llama.cpp ARM Android Q4_0 Q8_0

    llama.cpp: Q4_0 / Q8_0 repack kernels for ARMv8.0 targets without dotprod (#32142)

    ggml-cpu gained optimized repack kernels for Q4_0 / Q8_0 on 64-bit ARMv8.0 CPUs without the dotprod extension (Apple targets excluded), relevant to CPU inference on older or low-end Android devices.

    Source: https://github.com/ggml-org/llama.cpp/commit/f20c5907c00c1a7edc32209aa97df992152b10b8

    llama.cpp OpenCL MoE mxfp4

    llama.cpp: OpenCL coopmat MoE kernel added (#32971)

    The OpenCL backend added a cooperative-matrix MoE kernel covering q4_0 / q4_1 / q4_k / q5_0 / q5_1 / q5_k / q6_k / mxfp4. A fix for GDN QK offsets in OpenCL (#32747) also landed around the same time.

    Source: https://github.com/ggml-org/llama.cpp/commit/e6443bd7eb970d940b0669cd9ea0d82d91d620a1

    llama.cpp llama-quantize mixed precision b12669

    llama.cpp b12669: llama-quantize can now pick quant types automatically to hit a target size

    llama-quantize gains a --target-size option that automatically chooses the mix of quant types with the lowest error for a given file size or bits-per-weight target (PR #15550). This makes it easier to produce GGUFs that fit a device's memory budget. The build also fixes a linking bug with BUILD_SHARED_LIBS=OFF.

    Source: https://github.com/ggml-org/llama.cpp/releases/tag/b12669

    llama.cpp Metal BF16 b12668

    llama.cpp b12668: Metal MUL_MAT / MUL_MAT_ID support BF16 and F32 src1

    The Metal backend now accepts BF16 and F32-precision src1 for MUL_MAT and the MoE MUL_MAT_ID op (PR #32677), including BF16 support without the tensor API and a cleanup of the MoE precision policy.

    Source: https://github.com/ggml-org/llama.cpp/releases/tag/b12668

    5 items
    9B Q4_K_M / Q5_K_M / Q8_0 vision SenseNova

    SenseNova publishes official GGUF of SenseNova-Loop-9B

    Official GGUF of SenseNova's 9B image+text model (released 2026-11-17). It is a looped decoder that runs part of its layers twice, supports up to 512K context and is Apache 2.0. The model card points to OpenSenseNova's llama.cpp fork; upstream support is not stated.

    Source: https://huggingface.co/sensenova/SenseNova-Loop-9B-GGUF

    4B Q4_K_M〜IQ2_M bartowski

    bartowski publishes GGUF of Spark-X2.6-4B

    GGUF of XHToken's 4B model with 22 quantizations from BF16 to IQ2_M (Q4_K_M about 2.6 GB). It has a low/high thinking-effort setting, supports English and Chinese, and is Apache-2.0. A 1.7B GGUF is also available.

    Source: https://huggingface.co/bartowski/Spark-X2.6-4B-GGUF

    llama.cpp 新アーキテクチャ 8B (A1B)

    llama.cpp adds support for Zyphra's Zaya1 8B architecture

    PR #32071, merged on 2026-11-18, lets llama.cpp run Zaya1, a hybrid of CCA layers, standard attention layers and a top-1 routed MoE FFN (8B total / 1B active).

    Source: https://github.com/ggml-org/llama.cpp/pull/32071

    llama.cpp Vulkan b12612

    llama.cpp b12612: faster Vulkan MMVQ on AMD RDNA4

    Improves Vulkan quantized matrix-vector multiply for Q3_K, Q5_K and IQ4_XS on RDNA4 GPUs, keeping the default on AMD's proprietary driver, and cleans up shader loading (PR #31804).

    Source: https://github.com/ggml-org/llama.cpp/releases/tag/b12612

    llama.cpp 不具合修正 NVFP4

    llama.cpp b12611: fix missing scales in NVFP4 MoE experts

    Fixes NVFP4 MoE experts in some layers being copied before their per-expert scales were attached at load time, so they ran without scales (PR #32704).

    Source: https://github.com/ggml-org/llama.cpp/releases/tag/b12611
