GGUF モデル最新情報

GGUF 形式で使えるモデルの新着・更新、llama.cpp / Ollama / LM Studio などの関連アップデートを毎日まとめています。出典リンクから一次情報を確認できます。日付は日本時間です。

    llama.cpp bugfix b12779

    llama.cpp b12779：Hadamard 折り込み済みモデルを -sm tensor で読み込んだ際のクラッシュを明確なエラーに変更（#33080）

    prism.hadamard を使う Prism Bonsai 系モデルを分割モード tensor（-sm tensor）で読み込むと、meta バックエンドで GGML_ASSERT により異常終了していた。この修正で、該当モデルではこの分割モードを受け付けず、理由を示すメッセージを出して読み込みを中止するようになった。

    出典: https://github.com/ggml-org/llama.cpp/releases/tag/b12779

    12B (MoE, 2.5B active) Q4_K_M IQ4_XS Q8_0 coding

    JetBrains のコーディング向け MoE「Mellum2.1 Instruct」12B の GGUF を bartowski が公開

    JetBrains の Mellum2.1-12B-A2.5B-Instruct（総 12B・アクティブ 2.5B の MoE、Apache 2.0）を bartowski が imatrix 量子化で GGUF 化。思考過程を出さずに直接答える指示追従版で、エージェント的なコーディング用途を想定している。IQ2_M（約 5.4GB）から bf16 まで揃い、推奨は Q4_K_M（約 8.8GB）。llama.cpp b12600 以降が必要とされる。

    出典: https://huggingface.co/bartowski/Mellum2.1-12B-A2.5B-Instruct-GGUF

    llama.cpp release v1.1.0

    llama.cpp v1.1.0 を正式リリース

    1.0.0 に続くセマンティックバージョンの正式版として v1.1.0 タグが 2026-11-26 に作成された。本体のバージョン番号を 1.1.0 に上げる変更（#33043）がマージされ、同時期に ggml 側も 1.1.x に更新されている。

    出典: https://github.com/ggml-org/llama.cpp/releases/tag/v1.1.0

    llama.cpp Hexagon Snapdragon NPU

    llama.cpp：ggml-hexagon 2.0 で INT-HMX（W8A8）行列積や F16 自動変換に対応（#32582）

    Snapdragon NPU 向けの Hexagon バックエンドが大幅改修された。HMX による W8A8 整数行列積（既定のモード）、F32 から F16 への自動変換、汎用 DMA パイプライン、Q8_0 KV の Flash Attention などを追加し、RoPE・softmax・SSM 系など多くの演算も F16/DMA 対応で最適化。Snapdragon 向けドキュメントも更新された。

    出典: https://github.com/ggml-org/llama.cpp/commit/e0f884d4058d7acc117eb768a0a1c5290d0a8b94

    llama.cpp OpenCL Adreno Android

    llama.cpp：OpenCL で Adreno A850 向け MoE int8 カーネルと投機的デコード検証用 GEMV を追加

    Adreno A850 向けの MoE int8 カーネルのホスト側処理が追加された（#33069）。あわせて、投機的デコードの検証ステップで使う複数トークンの F32 GEMV が OpenCL に追加された（#33098、Qualcomm の開発者が共著）。

    出典: https://github.com/ggml-org/llama.cpp/commit/47d6192fce301f627c4d3e1c6910588c364dce0e

    llama.cpp が Inkling 2 の DSpark 投機的デコードに対応（#32218）

    公式リポジトリに Inkling 2 向け DSpark（ドラフト生成による投機的デコード）対応がマージされた。変換スクリプトと C++ 側の実装が追加され、temperature > 0 時の処理やドラフト状態幅・再シード順の修正、他の DSpark 実装とドラフトトークン数の扱いを揃える変更が含まれる。

    llama.cpp ARM Android Q4_0 Q8_0

    llama.cpp：dotprod 非対応の ARMv8.0 向けに Q4_0 / Q8_0 のリパックカーネルを追加（#32142）

    ggml-cpu に、dotprod 命令を持たない 64bit ARMv8.0 CPU 向けの最適化リパックカーネル（Q4_0 / Q8_0）が追加された。Apple 向けアーキテクチャは対象外。古い・廉価な Android 端末での CPU 推論に関係する変更。

    出典: https://github.com/ggml-org/llama.cpp/commit/f20c5907c00c1a7edc32209aa97df992152b10b8

    llama.cpp OpenCL MoE mxfp4

    llama.cpp：OpenCL に MoE 向け coopmat カーネルを追加（#32971）

    OpenCL バックエンドに、cooperative matrix を使う MoE 用カーネルが追加された。対応量子化は q4_0 / q4_1 / q4_k / q5_0 / q5_1 / q5_k / q6_k / mxfp4。同時期に OpenCL の GDN の QK オフセット修正（#32747）も入っている。

    出典: https://github.com/ggml-org/llama.cpp/commit/e6443bd7eb970d940b0669cd9ea0d82d91d620a1

    llama.cpp llama-quantize mixed precision b12669

    llama.cpp b12669：目標サイズに合わせて量子化タイプを自動選択する llama-quantize の新オプション

    llama-quantize に --target-size オプションが追加され、指定したファイルサイズまたは bpw（1重みあたりのビット数）に収まるよう、誤差が最小になる量子化タイプの組み合わせを自動で選べるようになった（PR #15550）。スマホなどメモリ容量が限られた端末向けに、容量ぴったりのGGUFを作りやすくなる。BUILD_SHARED_LIBS=OFF でのリンク不具合の修正も含む。

    出典: https://github.com/ggml-org/llama.cpp/releases/tag/b12669

    llama.cpp Metal BF16 b12668

    llama.cpp b12668：Metal の MUL_MAT / MUL_MAT_ID が BF16・F32 入力に対応

    Apple GPU 向け Metal バックエンドで、行列積（MUL_MAT と MoE 用の MUL_MAT_ID）の入力側（src1）に BF16 と F32 精度を使えるようにする変更（PR #32677）。テンソルAPIが無い環境での BF16 対応や、MoE の精度ポリシー整理も含む。

    出典: https://github.com/ggml-org/llama.cpp/releases/tag/b12668
