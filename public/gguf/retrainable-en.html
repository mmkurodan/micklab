GGUF Generator / Proprietary Format

Retrainable GGUF

Every GGUF exported by GGUF Generator is a Retrainable GGUF — a file you can reload at any time and keep training. Where a standard quantized GGUF is inference-only, a Retrainable GGUF preserves the model weights and metadata needed to resume training immediately in Interactive mode.

How It Differs from a Standard GGUF

Aspect Standard quantized GGUF Retrainable GGUF
Primary use Inference (text generation) Inference + continued training
Weight precision Quantized (Q4, Q8, etc.) F32 (full precision), F16, or Q8_0
Continued training Not supported Resume instantly via LOAD GGUF
Architecture LLaMA / Mistral / LFM2, etc. GGUF Generator's own small Transformer
File size Depends on params & quant type Depends on params & precision (F32 ≈ a few MB for 1M params)
llama.cpp compatibility Compatible GGUF format-compatible (architecture is proprietary)

Retraining Flow in Interactive Mode

The most direct way to use a Retrainable GGUF is Interactive (New GGUF) mode.

① Start
Tap NEW to create a fresh model, or LOAD GGUF to resume from an existing Retrainable GGUF.
② Train
NEW LEARN (new pair) / RESPONSE LEARN (correct last reply) update the model weights in real time.
③ Verify
TRY INFERENCE checks the model's current response. Wrong answers trigger automatic re-injection and another training step.
④ Export
EXPORT GGUF saves a Retrainable GGUF. Load it next session to pick up exactly where you left off.
EXPORT GGUF lets you choose the quantization format (F32 / F16 / Q8_0). F32 is best for continued training but produces larger files. Q8_0 is a good balance between precision and file size.

Architecture Details

Retrainable GGUF targets the small Transformer architecture designed by GGUF Generator:

  • pre-RMSNorm: RMS normalization applied before each block.
  • RoPE (Rotary Position Embedding): Position encoding.
  • SwiGLU: Gating function in the feed-forward layer.
  • Tied output: Embedding and output projection share weights, reducing parameter count.
  • Configurable dimensions: dModel / ffDim / layers / ctx are freely set at creation time. Verified to work at ~1 million parameters.

The architecture is described in standard GGUF metadata, so the file format is compatible with the GGUF ecosystem — but inference engines need explicit support for this architecture to run it.

Continued Training via Refine Mode (Auto GGUF Gen)

Beyond Interactive mode, Auto GGUF Gen's Refine option lets you continue training an existing Retrainable GGUF in a batch workflow.

  • Select the base GGUF — model dimensions (dModel / ffDim / layers / ctx) are inherited automatically.
  • Supply new training data (JSONL) to extend or revise the model's knowledge without starting from scratch.
  • Use early stopping to limit overfitting while keeping training efficient.

Retrainable GGUF vs. LoRA

GGUF Generator also supports LoRA fine-tuning on existing LFM2 GGUFs. Here's how the two approaches compare:

Aspect Retrainable GGUF (own model) LoRA (existing LFM2 GGUF)
Base model None — trained from scratch Requires an existing LFM2 GGUF
What's trained All weights LoRA adapter weights only
Model capability Small model specialized on training data Base model capability + fine-tune
Reuse LOAD GGUF to resume training SAVE / RESTORE STATE for session continuity
Output Standalone GGUF Adapter GGUF + merged full GGUF (both)
