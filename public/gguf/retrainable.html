GGUF Generator / 独自形式

Retrainable GGUF

GGUF Generator が出力する GGUF ファイルは、再ロードしてそのまま追加学習できる独自の「Retrainable GGUF」形式です。一般的な量子化 GGUF が推論専用であるのに対し、この形式はモデルの重みと学習に必要なメタデータを保持し、インタラクティブモードで即座に学習を再開できます。

通常の GGUF との違い

項目 通常の量子化 GGUF Retrainable GGUF
主な用途 推論（テキスト生成） 推論 ＋ 追加学習
重みの精度 量子化（Q4/Q8 など） F32（フル精度）または F16 / Q8_0
追加学習 通常不可 LOAD GGUF からそのまま再開
アーキテクチャ LLaMA / Mistral / LFM2 など GGUF Generator 独自の小型 Transformer
ファイルサイズ パラメータ数・量子化に依存 パラメータ数・精度に依存（1M パラメータで F32 ≈ 数 MB）
llama.cpp 互換 互換 GGUF 形式として互換（ただしアーキテクチャは独自）

インタラクティブモードでの再学習フロー

Retrainable GGUF の最も典型的な使い方はインタラクティブ（新規 GGUF）モードです。

① 開始
NEW で新規モデルを作成、または LOAD GGUF で既存の Retrainable GGUF を読み込む
② 学習
NEW LEARN（新規ペア）/ RESPONSE LEARN（直前の応答を修正）でリアルタイムに重みを更新
③ 確認
TRY INFERENCE でモデルの応答を即確認。不正解なら自動で再注入（Re-inject）して続行
④ 書き出し
EXPORT GGUF で Retrainable GGUF を保存。次回は LOAD GGUF でそのまま再開
EXPORT GGUF は量子化形式（F32 / F16 / Q8_0）を選択して書き出します。F32 が最も再学習に適していますが、ファイルサイズが大きくなります。Q8_0 は精度と容量のバランスが良い選択肢です。

アーキテクチャの特徴

Retrainable GGUF が対象とするのは GGUF Generator が独自に設計した小型 Transformer です。主な構成は以下の通りです。

  • pre-RMSNorm: 各ブロック前に RMS 正規化を適用する標準構成
  • RoPE（Rotary Position Embedding）: 位置エンコーディング
  • SwiGLU: フィードフォワード層のゲーティング関数
  • Tied 出力: 埋め込み行列と出力投影を共有してパラメータ数を削減
  • モデル寸法: dModel / ffDim / layers / ctx を自由に設定可能。100 万パラメータ程度の極小モデルから動作確認済み

このアーキテクチャは llama.cpp が認識できる GGUF メタデータで記述されるため、ファイル形式としては標準 GGUF と互換ですが、推論エンジン側に当該アーキテクチャのサポートが必要です。

修正モード（Auto GGUF Gen）での継続学習

インタラクティブモード以外にも、Auto GGUF Gen の「修正（追加学習）」モードで既存の Retrainable GGUF を基点として継続学習することができます。

  • 基点 GGUF を選択すると、モデル寸法（dModel / ffDim / layers / ctx）は基点から自動で継承されます。
  • 新しい学習データ（JSONL）を用意するだけで、既存の知識を保ちながら内容を追加・修正できます。
  • 早期停止機能を使うことで、過学習のリスクを抑えながら効率よく学習できます。

LoRA との使い分け

GGUF Generator には LoRA 学習（LFM2 GGUF 対象）も搭載されています。Retrainable GGUF と LoRA はそれぞれ異なる用途に適しています。

観点 Retrainable GGUF（独自モデル） LoRA（既存 LFM2 GGUF）
ベースモデル なし（ゼロから作成） 既存の LFM2 GGUF が必要
学習対象 全重み LoRA アダプタのみ
モデルの能力 学習データに特化した小型モデル ベースモデルの能力＋追加ファインチューン
再利用性 LOAD GGUF で再学習 SAVE/RESTORE STATE でセッション再開
出力 単独ロード可能な GGUF アダプタ GGUF ＋ 統合版フル GGUF の両方
