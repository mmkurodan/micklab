操作マニュアル

このページは、現在の Android 実装に基づく OCR APIサーバー（旧 ClarityPDF）の操作ガイドです。アプリ内ドキュメントの内容をベースに、公開ページ向けに整理して掲載しています。

関連文書: プライバシーポリシー

1. 共通

  • ホームは上から「① OCR API サーバー（状態・開始/停止・ポート・接続先）」「② OCR / AI-OCR」「③ PDF 変換と構成」「④ PDF 作成と編集」「⑤ 環境設定」「⑥ 処理状況 / ログ」の順に並びます。②〜⑥は見出しをタップすると開閉します。
  • 入力ファイルは読み取りのみで、元ファイルは変更しません。結果は常に新しいファイルとして保存します。
  • 出力先は各画面の「出力先」で選べます。未指定なら端末の「Download/PDFToolkit」に保存します。

2. OCR API サーバー

ホーム最上部の「API を開始」を押すと、この端末が OCR API サーバーになります。PDF や画像を送ると文字情報を JSON で返します。端末内の他アプリや、同じ LAN 上の PC・他端末から利用できます。

⚠️ 認証はありません。信頼できるローカルネットワーク内でのみ使用し、外部ネットワークには公開しないでください。

常時稼働

  • 一度開始すると、アプリを閉じても通知付きのバックグラウンドサービスとして動き続け、プロセス終了後・端末再起動後も自動で再開します。止まるのは「API を停止」「終了」または通知の「停止」を押したとき、他アプリから停止要求を受けたときだけです。
  • ホームの「バッテリー最適化から除外する」を許可すると、スリープ中の応答と自動復帰が安定します（Android 12 以降はウォッチドッグによる復帰の前提になります）。
  • OCR 処理中は WakeLock と Wi-Fi ロックを保持し、画面オフでも処理を継続します。
  • ポートは停止中に変更できます。接続先のエンドポイント URL はタップでコピーできます。
  • 端末メーカー独自の省電力機能による強制停止（force-stop）からは復帰できない場合があります。

エンドポイント

用途URL
OCR リクエストPOST http://<端末IP>:<ポート>/ocr
端末内からPOST http://127.0.0.1:<ポート>/ocr
ヘルスチェックGET http://<端末IP>:<ポート>/health → {"status":"ok"}

既定のポートは 8765 です。

リクエスト（multipart/form-data）

フィールド必須説明
file○画像（PNG/JPEG/WebP/BMP）または PDF
enginetesseract（既定）| paddleocr | llm
lang言語コード、カンマ区切り（既定: eng）例: jpn / jpn,eng / jpn_vert（縦書き）/ chi_sim / kor
dpiPDF のレンダリング解像度 36〜600（既定 150）。応答にも返されます

レスポンス（HTTP 200）

{
  "pages": [ {
    "page": 1, "text": "認識されたテキスト", "confidence": 0.92, "source": "OCR",
    "width": 1080, "height": 2400,
    "blocks": [ { "text": "…", "confidence": 0.95,
                  "box": { "left": 40, "top": 120, "right": 620, "bottom": 168 } } ]
  } ],
  "engine": "Tesseract", "languages": ["jpn", "eng"], "dpi": 150, "pageCount": 1
}

blocks は認識した行ごとのテキストと位置です。box は OCR した画像（width × height、PDF は dpi でレンダリングした後のサイズ）上のピクセル座標で、原点は左上です。Tesseract と PaddleOCR は box を返し、位置を持たない LLM Vision では box を省略します。

エラー

HTTP内容
400{"error":"Missing 'file' field"} — file フィールドなし
400{"error":"Could not decode image"} — 画像デコード失敗
400{"error":"Unknown engine: xxx"} — engine 名が不正
500{"error":"..."} — OCR 処理エラー

curl 使用例

# JPEG を英語 Tesseract で OCR
curl -X POST http://192.168.1.10:8765/ocr \
     -F "file=@document.jpg" -F "engine=tesseract" -F "lang=eng"

# PDF を日本語+英語で OCR（複数ページ対応・300dpi）
curl -X POST http://192.168.1.10:8765/ocr \
     -F "file=@scan.pdf;type=application/pdf" -F "lang=jpn,eng" -F "dpi=300"

# 縦書きの日本語を PaddleOCR で
curl -X POST http://192.168.1.10:8765/ocr \
     -F "file=@tategaki.png" -F "engine=paddleocr" -F "lang=jpn_vert"

# ヘルスチェック
curl http://192.168.1.10:8765/health

Python 使用例

import requests

with open("document.pdf", "rb") as f:
    resp = requests.post(
        "http://192.168.1.10:8765/ocr",
        files={"file": ("document.pdf", f, "application/pdf")},
        data={"engine": "tesseract", "lang": "jpn,eng"},
    )
result = resp.json()
for page in result["pages"]:
    print(f"Page {page['page']}: {page['text'][:80]}...")
    for b in page.get("blocks", []):
        print("  ", b["text"], b.get("box"))

他アプリからの有効化（Intent）

サービスは exported です。明示的 Intent を startForegroundService() で送ると、本アプリの画面を開かずに API を開始／停止できます。呼び出し側はフォアグラウンド（画面表示中）である必要があります。

項目値
componentcom.micklab.pdf / com.micklab.pdf.api.OcrApiService
開始 actioncom.micklab.pdf.START_SERVICE（任意: int extra port、1024〜65535。省略時は保存済みポート）
停止 actioncom.micklab.pdf.STOP_SERVICE
// 呼び出し側 AndroidManifest.xml（Android 11+）:
// <queries><package android:name="com.micklab.pdf" /></queries>
val intent = Intent()
    .setClassName("com.micklab.pdf", "com.micklab.pdf.api.OcrApiService")
    .setAction("com.micklab.pdf.START_SERVICE")
    .putExtra("port", 8765)
ContextCompat.startForegroundService(context, intent)
// 起動確認: GET http://127.0.0.1:8765/health
adb shell am start-foreground-service -n com.micklab.pdf/.api.OcrApiService \
  -a com.micklab.pdf.START_SERVICE --ei port 8765
  • メーカーの自動起動制御（ZTE/Nubia の AutoLaunch など）で他アプリからの startForegroundService が拒否される端末向けに、透明な起動用 Activity（同じ action com.micklab.pdf.START_SERVICE、任意の int extra port）も用意しています。前面に出た本アプリが自分でサービスを開始します。
  • Android 13 以降で本アプリに通知権限がない場合もサービスは動作しますが、通知は表示されません（一度アプリを開いて「API を開始」を押すと権限を確認します）。
  • 大きな PDF は処理に時間がかかります（1 ページあたり数秒〜数十秒）。engine=tesseract で lang=jpn を使うには Tesseract 日本語モデルが必要です。PaddleOCR / LLM も各エンジンのモデル・設定が必要です。

3. OCR / AI-OCR（画面からの直接実行）

  • OCR / テキスト抽出: PDF・画像から文字を抽出します。埋め込みテキスト（元からある文字）と OCR（画像認識）を区別して JSON でも出力します。エンジンは Tesseract（軽量）/ PaddleOCR（高品質）から選べます。Tesseract は日本語（横書き・縦書き）・英語・中国語(簡体/繁体)・韓国語・ギリシャ語・ロシア語(キリル)・アラビア語・ヘブライ語・数式(equ)に、PaddleOCR は日本語（横書き・縦書き）・英語・中国語(簡体/繁体)・韓国語・アラビア語・キリル文字に対応します（各言語モデルは初回のみ取得）。大きな文書はバックグラウンド実行が可能です。
  • PDF サマリ（要約）: ファイル全体・ページごとを LLM で要約します。「OCR→LLM」または「Vision（ページ画像を直接 LLM へ）」を選べます。
  • AI プロンプト: 任意の指示（プロンプト）を入力し、PDF 全体または各ページごとに AI 処理を実行できます。方式は「OCR→LLM」または「Vision」を選べます。実行中はボタンが「中止」に変わり、処理を止められます。
  • モデルを初めて使うときは、読み込みに時間がかかる旨の確認が表示されます。Vision モデルが未設定（プレースホルダ）の場合は警告が表示されます。

4. PDF 変換と構成

  • 分解（ページ抽出）: PDF を開き、抽出したいページを選択 → 1 つにまとめる／ページごとに分ける、を選んで出力。
  • 統合（結合）: 複数の PDF を選び、順序を整えて 1 つに結合します。
  • 並べ替え: サムネイルをドラッグしてページ順を入れ替え、新しい PDF として保存します。
  • PDF 画像化: 各ページを PNG / JPEG に変換します。DPI（解像度）を指定できます。
  • 画像 → PDF 化: 複数の画像を選び、順序を指定して 1 つの PDF にまとめます。

5. PDF 作成と編集

  1. 「PDF を選択」で編集する PDF を開くか、「白紙から新規作成」で用紙サイズ・背景色を指定して空ページを作成します。既存 PDF を開いた時／新規作成時は、テキストの追加・変更・移動でフォントや書式が元と変わる場合がある旨の注意が表示されます。
  2. プレビュー下部の「◀ 前／次 ▶」でページを移動します。ページ操作メニューから空白ページの挿入（現在ページの前／後／末尾）、削除ボタンで現在ページの削除ができます（ページが 1 枚のときは削除不可）。
  3. テキストを追加: 文字を入力（改行可）→ サイズ・色・スタイル・フォントを選び「追加」。プレビュー上に置かれるのでドラッグで移動します。
  4. 画像を追加: 「画像」で画像を選ぶとプレビューに配置されます。ドラッグで移動、拡大縮小・回転できます。
  5. 図形を追加: 「図形」で四角／楕円、枠線色・塗り・線の太さを選び、キャンバス上をドラッグして描きます。
  6. 描画: 「描画」でブラシの色・太さを選び、フリーハンドで描きます（元に戻すに対応）。
  7. 背景色: 「背景」で色を選び「適用」すると、ページ全体に背景色を敷きます。
  8. 既存の文字を編集: プレビュー上の文字をタップすると選択されます。「置換後の文」を入力、または「元の文字を削除」を選びます。明示的に変更しない限り、元のフォント・サイズ・色・スタイルを引き継ぎます。
  9. レイヤー: 追加・編集した項目は「レイヤー」に一覧表示されます。タップで選択、▲▼で重なり順の変更、× で削除できます。
  10. 「決定」でその時点の編集を一時 PDF に反映してプレビューを更新します。図形・描画は「決定」後もレイヤーとして残ります。
  11. 「適用して保存」で最終的な PDF を出力します。保存せずに戻ろうとすると確認が表示されます。

※ テキストの追加・編集には埋め込みフォントが必要です。Noto Sans JP / Noto Serif JP / M PLUS Rounded 1c / Zen Kaku Gothic New / Klee One / Noto Sans / Noto Sans SC / TC / KR / Noto Sans Arabic / Hebrew / Noto Sans Math / Symbols 2（すべて SIL OFL）から選べ、フォント選択時にその場でダウンロードされます（初回のみ通信）。Noto 系はカバーする文字種（例: 中国語(簡体)）で表示されます。アラビア語・ヘブライ語（右→左）は入力時に自動で連結整形・双方向並べ替えを行います。

6. 環境設定

  • OCR 設定・モデル管理: Tesseract / PaddleOCR の言語モデル取得、LLM（Ollama / OpenAI 互換）の接続 URL・モデル選択・接続確認。順序は Tesseract → PaddleOCR → LLM です。
  • LLM の既定値と自動起動: Vision（OCR）モデルの既定は「default Vision」、テキストモデルは「default Chat」（コンパニオンアプリ LLM AI Server with llama.cpp の同梱構成）。LLM サーバーが停止中の場合は、要約・OCR などの処理を始めたときに自動で起動を試みます。
  • 言語設定: 日本語 / English / Français / Deutsch / Español / Italiano / Português / 中文（简体）/ 한국어。
  • 操作マニュアル / プライバシーポリシー / 権利表記: 本ドキュメント類（各画面で本文をコピーできます）。

7. 処理状況 / ログ・オフラインについて

  • ホームの「処理状況 / ログ」で、API の開始・停止・リクエスト・エラーの履歴を確認できます。
  • PDF・画像処理は端末内で完結します。通信するのは「OCR モデル・フォントの初回ダウンロード」「LLM を利用する場合の設定サーバへの送信」「広告の表示」だけです（既定の LLM 接続先は端末内 127.0.0.1）。
  • 外部 LLM サーバを指定した場合、ページ画像や抽出テキストはその接続先へ送信されます。送信先はご自身の設定に依存します。
